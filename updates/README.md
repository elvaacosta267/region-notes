# updates/ 사용법

업데이트 루프를 실행할 때마다 그날 날짜로 파일을 하나씩 추가합니다: `YYYY-MM-DD.md`

이 루프는 사용자가 대화 중 수동으로 요청할 수도 있고, 예약된(cron) 에이전트가 부동산
뉴스·구청/시청 고시를 주기적으로 확인해 자동으로 돌릴 수도 있습니다 — 어느 쪽이든
아래 형식은 동일해야 합니다. `tools/build_geo.py`가 이 폴더의 `.md` 파일들을 파싱해서
각 사업의 "최근 업데이트" 배지(순위표 앱에 표시)를 만들기 때문에, **`- [id: ...]` 줄과
그 바로 아래 `  - 출처: URL` 줄의 형식을 정확히 지켜야 합니다.**

## 템플릿

```md
# 2026-08-15 업데이트

## 변경 사항
- [id: P306] 청천4구역 재개발 — 사업시행인가 취득
  - 출처: https://example.go.kr/notice/12345
- [id: P205] 산본9-2구역 재건축 — 실시계획 승인 고시
  - 출처: https://example.go.kr/notice/67890

## 신규 추가
- (해당 회차에 새로 추적을 시작한 사업이 있으면 기재)

## 특이사항
- (여론, 지연 사유, 관련 소송 등 자유 기술)
```

`[id: ...]` 의 값은 반드시 `db/plans.csv`의 실제 `id` 컬럼 값(예: `P306`)과 정확히
일치해야 합니다 — 다르면 배지가 해당 사업에 연결되지 않습니다.

## 원칙
- 하나의 업데이트 로그 = 하나의 대화 세션(또는 예약 작업 1회 실행).
- `plans.csv`의 변경분과 반드시 1:1로 대응해야 함 (로그에 없는 csv 변경은 만들지 않는다).
- 출처 URL 없는 변경은 기록하지 않는다.
- 예약 작업이 만든 변경은 곧바로 main에 커밋하지 않고 **항상 PR로 올려 사용자 검토를
  거친다** (오탐지 위험 — 다른 사업과 이름이 비슷하거나 오래된 기사를 잘못 매칭할 수 있음).
