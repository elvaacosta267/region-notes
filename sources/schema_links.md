# links_db.csv 스키마 정의

국가·지자체 개발계획 원문을 어디서 구할 수 있는지 추적하는 "수집 대상 출처 문서" 목록이다. `db/plans.csv`(추적 대상 사업의 진행상황)와는 성격이 다른 별도 테이블이며, FK로 억지로 연결하지 않는다 — 지금 규모(131행, 수작업 큐레이션)에서는 `plans.csv`의 비고란에 `링크#76`처럼 느슨하게 인용하는 정도로 충분하다.

## PDF 원본 보관 원칙

**원문 PDF는 이 저장소(git)에 올리지 않는다.** GitHub는 파일 하나가 100MB를 넘으면 업로드 자체가 막히고, 저장소 전체도 1GB 안팎을 권장 상한으로 본다 — 이 목록의 원문을 다 모으면 수십 GB에 달할 수 있어 git 히스토리를 감당할 수 없다.

대신:
- 사용자가 로컬 또는 개인 클라우드 드라이브에 원본 PDF를 보관한다(git과 무관, 이 저장소가 관여하지 않음).
- 이 저장소에는 **원문 링크(위 `링크` 컬럼) + 요약 md(`docs/plans/*.md`)만** 커밋한다. 요약이 틀렸을 수 있는 문서(예: OCR 실패로 2차 출처 교차검증한 문서)는 원본 대조가 특히 중요하므로, 그런 경우일수록 원본을 지우지 말고 로컬에 남겨둔다.

## 활용 방식

새 지역/계획을 `db/plans.csv`에 편입할 때, 이 목록에서 해당 "레벨"(예: 파일럿 확장 시 ③정비재생 → 시군구별 정비사업 오픈데이터)을 먼저 확인하고 원문 확보 상태(`상태` 컬럼)를 참고한다. `미확보` 항목은 직접 리서치(뉴스 검색, 웹서치)로 보완해야 한다.
